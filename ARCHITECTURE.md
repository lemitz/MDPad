# MDPad: архитектура текстового редактора

Рабочее название: **MDPad**. Блокнот для Windows 10/11 с нативной поддержкой Markdown. Фокус на `.md`, `.txt` тоже открываются и редактируются.

---

## 1. Требования (из обсуждения)

| Параметр | Решение |
|---|---|
| Платформа | Windows 10/11 (десктоп) |
| Форматы | `.md`, `.markdown`, `.txt`. Остальное, по желанию, открывается как plain text |
| Markdown | Корректная интерпретация CommonMark + GFM (таблицы, чекбоксы, зачёркивание, автоссылки) |
| Редактирование | Как в блокноте/Word: выделение, отмена/повтор, буфер, перенос строк, номера строк |
| Вкладки | Несколько документов в одном окне |
| Поиск | Поиск и замена в документе (Ctrl+F / Ctrl+H) |
| Превью | Режимы: только редактор / сплит / только превью |
| Тема | Только тёмная |
| Хоткеи | Только стандартные, по логике Word/Блокнота |
| Масштаб | Личный проект, без телеметрии, без автообновлений, без облака |

---

## 2. Стек

**Выбор: Tauri 2 (Rust-ядро + системный WebView2) + TypeScript + Vite + CodeMirror 6 + markdown-it.**

Почему так:

- **Лёгкость.** Tauri использует WebView2, который уже стоит в Windows 10/11. Установщик будет порядка 5–10 МБ, против 100+ МБ у Electron. Память тоже заметно меньше.
- **Редактор.** CodeMirror 6 даёт всё, что нужно для блокнота: мультикурсор, отмена/повтор, поиск с заменой, подсветка Markdown, номера строк, перенос строк. Писать это с нуля не нужно.
- **Превью.** markdown-it выдаёт HTML по спецификации CommonMark, плагины закрывают GFM. Рендер идёт в обычной вебвью, поэтому вёрстка превью пишется обычным CSS.

Отвергнутые варианты:
- **Electron.** Тяжёлый, противоречит требованию легковесности.
- **Python + PySide6/Qt.** Громоздкая сборка (сотни МБ), превью через QtWebEngine тяжёлое.
- **C# + WPF.** Нативно и легко, но редактор с подсветкой и превью Markdown собирать дольше. Запасной вариант.

## 3. Архитектура в целом

Два слоя с чётко разделённой ответственностью:

```
┌──────────────────────────── Tauri window (WebView2) ────────────────────────────┐
│  UI (TypeScript)                                                                 │
│  ┌──────────┐ ┌────────────────┐ ┌──────────────┐ ┌──────────────────────────┐  │
│  │ TabBar   │ │ Editor (CM6)   │ │ Preview      │ │ SearchPanel / StatusBar  │  │
│  └────┬─────┘ └───────┬────────┘ └──────┬───────┘ └────────────┬─────────────┘  │
│       └───────────────┴─────────┬───────┴──────────────────────┘                │
│                                 ▼                                                │
│        AppState store  ◄── Commands / Keymap registry                           │
│                 │                                                                │
│        Markdown pipeline (markdown-it → sanitize → DOM)                         │
│                 │ invoke()                                                       │
└─────────────────┼────────────────────────────────────────────────────────────────┘
                  ▼  IPC (Tauri commands)
┌──────────────────────────── Rust core ───────────────────────────────────────────┐
│  fs_service      чтение/запись файлов, атомарная запись                          │
│  encoding_service определение кодировки и EOL (UTF-8, UTF-8 BOM, UTF-16, CP1251)  │
│  dialog_service  системные диалоги Открыть/Сохранить                             │
│  settings_service сохранение настроек и списка недавних файлов                   │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Принцип: **Rust ничего не знает о Markdown и редактировании.** Он только читает и пишет файлы, определяет кодировку и показывает диалоги. Вся логика документа и UI живёт во фронтенде.

## 4. Модель данных

```ts
type DocKind = 'markdown' | 'plain';

interface Document {
  id: string;               // uuid, внутренний
  path: string | null;      // null для нового документа
  title: string;            // имя файла или "Без имени N"
  kind: DocKind;            // по расширению; .txt → plain
  encoding: 'utf-8' | 'utf-8-bom' | 'utf-16le' | 'utf-16be' | 'windows-1251';
  eol: '\r\n' | '\n';       // сохраняем то, что было в файле
  savedText: string;        // последнее сохранённое содержимое
  dirty: boolean;           // текущий текст !== savedText
  // Состояние редактора (курсор, скролл, undo-история) хранится в EditorState CM6
}

interface AppState {
  tabs: Document[];
  activeTabId: string;
  viewMode: 'editor' | 'split' | 'preview';
  search: { query: string; replace: string; caseSensitive: boolean; regexp: boolean };
  settings: { fontFamily: string; fontSize: number; wordWrap: boolean; showLineNumbers: boolean };
  recentFiles: string[];
}
```

Важно: при сохранении `eol` и `encoding` берутся из документа, а не выбираются заново. Так файл не меняет формат при каждом сохранении.

## 5. IPC-контракт (фронт ↔ Rust)

| Команда | Вход | Выход | Заметки |
|---|---|---|---|
| `open_file` | `path` | `{ text, encoding, eol }` | Определяет кодировку, нормализует переводы строк для редактора |
| `save_file` | `path, text, encoding, eol` | `void` | Атомарно: пишем во временный файл и переименовываем |
| `pick_open_path` | `-` | `path \| null` | Системный диалог, фильтры `*.md`, `*.txt`, все |
| `pick_save_path` | `suggestedName` | `path \| null` | Системный диалог |
| `load_settings` / `save_settings` | `settings` | `settings` | JSON в `%APPDATA%\MDPad\` |
| `list_recent` / `push_recent` | `path` | `string[]` | Для меню «Недавние» |

## 6. Ключевые модули (фронтенд)

1. **Editor.** Обёртка над CodeMirror 6. Расширения: `markdown()` с подсветкой, `search()`, `history()`, `lineNumbers()`, `highlightActiveLine()`, `EditorView.lineWrapping`, тёмная тема на CSS-переменных. Для `.txt` подсветка Markdown отключается.
2. **Preview.** Конвейер: `markdown-it` (CommonMark + плагины: GFM-таблицы, task-list, linkify, strikethrough) → `DOMPurify` (очистка HTML) → контейнер. Обновление с дебаунсом ~150 мс. Синхронизация скролла редактор ↔ превью по доле прокрутки.
3. **TabBar.** Список `Document`, переключение, закрытие с проверкой `dirty` (диалог «Сохранить / Не сохранять / Отмена»). Каждая вкладка хранит свой `EditorState`, поэтому undo-история и позиция курсора сохраняются при переключении.
4. **SearchPanel.** Используется встроенный `search()` из CM6. Панель с полями Найти/Заменить, опции регистра и регулярных выражений, Enter/Shift+Enter.
5. **Commands + Keymap.** Все действия описаны как команды (`file.save`, `view.togglePreview`, `tab.next` и т. д.). Хоткеи лежат в одной таблице, что упрощает правки и проверку конфликтов.
6. **Theme.** Один набор CSS-переменных (`--bg`, `--fg`, `--accent`, `--muted` и т. д.). Светлой темы нет и не будет.

## 7. Поток данных (пример: сохранение)

1. Пользователь нажимает Ctrl+S.
2. Команда `file.save` берёт активный `Document`.
3. Если `path === null`, вызывается `pick_save_path`.
4. Текст берётся из `EditorState.doc.toString()`.
5. Вызывается `save_file(path, text, encoding, eol)`.
6. При успехе: `savedText = text`, `dirty = false`, путь в `push_recent`, обновляется заголовок окна и вкладки.

Поток редактирования: ввод → CM6 `updateListener` → пометка `dirty` → дебаунс → перерисовка превью.

## 8. Кодировки и переводы строк

Важно для русскоязычных файлов:

- Определение кодировки в Rust через `chardetng` и `encoding_rs`. Поддерживаем UTF-8 (с BOM и без), UTF-16 LE/BE и Windows-1251. Остальное открывается как UTF-8 с заменой битых байтов.
- Перевод строк: `\r\n` или `\n` определяется по первому переводу строки в файле. В редакторе всё хранится как `\n`, при записи возвращается исходный вариант.
- Новый файл сохраняется как UTF-8 без BOM с `\r\n` (стандарт Windows).

## 9. Горячие клавиши (стандартные, как в Word и Блокноте)

| Действие | Клавиши |
|---|---|
| Новый / Открыть / Сохранить / Сохранить как | Ctrl+N / Ctrl+O / Ctrl+S / Ctrl+Shift+S |
| Закрыть вкладку | Ctrl+W |
| Следующая / предыдущая вкладка | Ctrl+Tab / Ctrl+Shift+Tab |
| Отмена / повтор | Ctrl+Z / Ctrl+Y (и Ctrl+Shift+Z) |
| Вырезать / копировать / вставить / выделить всё | Ctrl+X / C / V / A |
| Найти / заменить / перейти к строке | Ctrl+F / Ctrl+H / Ctrl+G |
| Жирный / курсив (оборачивает выделение `**` / `*`) | Ctrl+B / Ctrl+I |
| Переключить превью | Ctrl+Shift+V (или Ctrl+Shift+M) |
| Увеличить / уменьшить / сбросить шрифт | Ctrl+колесо / Ctrl+= / Ctrl+- / Ctrl+0 |

Ctrl+B и Ctrl+I только для Markdown. В `.txt` они ничего не делают.

## 11. Нефункциональные требования

- Установщик: до 10 МБ. Портативный `.exe` без установки: желательно.
- Холодный старт: до 1 секунды на среднем железе.
- Файлы до ~10 МБ открываются без подтормаживания (CM6 справляется).
- Сохранение атомарное: сбой не должен портить файл.
- Никакой сети, телеметрии и автообновлений.

## 12. Фазы разработки

1. **Каркас.** Tauri + Vite + TS, пустое окно с тёмной темой, меню и статус-бар.
2. **Файлы.** Открыть / сохранить / сохранить как, кодировки, EOL, диалог несохранённых изменений.
3. **Редактор.** CM6, подсветка Markdown, номера строк, перенос строк, отмена/повтор.
4. **Вкладки.** Многодокументность, переключение, закрытие, недавние файлы.
5. **Превью.** markdown-it + GFM, очистка HTML, режимы editor/split/preview, синхронизация скролла.
6. **Поиск.** Найти / заменить / перейти к строке, опции регистра и regex.
7. **Хоткеи и полировка.** Таблица клавиш, Ctrl+B/I, масштаб, восстановление сессии при запуске.
8. **Сборка.** Установщик и портативная версия, ручное тестирование на Windows 10 и 11.
