---

MDPad — нечто среднее между Блокнотом и полноценной Markdown-IDE: запускается мгновенно, ощущается как обычный текстовый редактор, но понимает Markdown — подсвечивает синтаксис прямо во время набора и показывает рядом точное превью CommonMark + GFM. Построен на [Tauri 2](https://tauri.app), поэтому использует уже имеющийся в Windows рантайм WebView2 вместо встроенного браузерного движка.

## Возможности

**Редактор**
- Редактор на [CodeMirror 6](https://codemirror.net): подсветка синтаксиса Markdown, история отмены и повтора, подсветка активной строки, парные скобки и подсветка совпадений с выделением
- Поиск и замена (`Ctrl+F` / `Ctrl+H`), переход к строке (`Ctrl+G`)
- `Ctrl+B` / `Ctrl+I` оборачивают выделение в `**` / `*`, повторное нажатие снимает обёртку (только в Markdown-документах)
- Номера строк и мягкий перенос, переключаются на лету
- Масштаб шрифта: `Ctrl` + колесо мыши, `Ctrl+=` / `Ctrl+-`, сброс — `Ctrl+0`
- Горячие клавиши сопоставляются по физической клавише и работают в нелатинских раскладках (например, `Ctrl+S` в русской раскладке)

**Превью**
- CommonMark + GitHub Flavored Markdown: таблицы, списки задач, зачёркивание, автоссылки
- Рендер через [markdown-it](https://github.com/markdown-it/markdown-it); сырой HTML в документах не отображается, а результат очищается [DOMPurify](https://github.com/cure53/DOMPurify)
- Широкие таблицы прокручиваются по горизонтали внутри превью; текст чекбоксов переносится как обычно
- Обновляется по мере набора (с задержкой); пока превью скрыто, рендер приостановлен
- Правка прямо в превью: двойной клик по блоку (абзац, заголовок, элемент списка, таблица, код…) открывает его Markdown для правки на месте; двойной клик ниже текста добавляет новый блок. `Ctrl+Enter` или клик снаружи завершает правку, `Esc` отменяет. Изменения сразу попадают в документ, поэтому отмена (`Ctrl+Z` работает и в режиме рендера), маркер несохранённых изменений и сплит остаются согласованными
- Чекбоксы списков задач кликабельны и переключают `[ ]` / `[x]` в исходнике

**Раскладка**
- Три режима: **разметка** (только исходник), **рендер** (только превью) и **сплит** (`Ctrl+Shift+V`)
- Сплит с перетаскиваемым разделителем: утащите его к краю, чтобы свернуть панель, двойной клик возвращает 50/50
- Необязательная синхронизация позиции редактора и превью по строкам исходника: двусторонняя прокрутка в сплите, а при переключении разметка ↔ рендер ↔ сплит или раскрытии свёрнутой панели на экране остаётся то же место документа
- Каждая вкладка помнит позицию в каждом режиме
- Окно без рамки с собственной строкой заголовка, только тёмная тема

**Вкладки**
- Несколько документов в одном окне, переключение — `Ctrl+Tab` / `Ctrl+Shift+Tab`
- Закрытие — `Ctrl+W` или средний клик; точка отмечает несохранённые вкладки
- Запрос «Сохранить / Не сохранять / Отмена» перед закрытием несохранённой вкладки или окна
- Закрытие последней вкладки закрывает приложение
- Необязательное восстановление сессии: при следующем запуске откроются те же вкладки (включая несохранённые черновики)

**Файлы и кодировки**
- Открытие через диалог (с выбором нескольких файлов), перетаскиванием из Проводника, из командной строки (`mdpad.exe notes.md`) или двойным кликом по `.md`-файлу
- Один экземпляр: при открытии ещё одного файла запущенное окно выходит на передний план и получает новую вкладку
- Кодировки UTF-8, UTF-8 с BOM, UTF-16 LE/BE и Windows-1251 определяются автоматически и сохраняются при записи
- Окончания строк `CRLF` / `LF` тоже сохраняются; новые файлы записываются как UTF-8 без BOM с `CRLF`
- Атомарная запись: файл пишется во временный файл рядом с оригиналом, сбрасывается на диск и затем переименовывается поверх него — сбой посреди записи никогда не оставит обрезанный файл
- Любое другое расширение открывается как простой текст; «Сохранить как» с расширением `.md` переключает вкладку в режим Markdown
- Строка состояния показывает строку и столбец, число символов, кодировку, окончание строк и тип документа

**Остальное**
- Интерфейс на английском, а если язык Windows русский — на русском
- Настройки (`Ctrl+,`): восстановление вкладок при запуске, перенос длинных строк, номера строк, синхронная прокрутка
- Без телеметрии, без автообновлений, без доступа в сеть (политика безопасности контента разрешает только локальные ресурсы)

## Горячие клавиши

| Действие | Клавиши |
|---|---|
| Новый / Открыть / Сохранить / Сохранить как | `Ctrl+N` / `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` |
| Закрыть вкладку | `Ctrl+W` (или средний клик по вкладке) |
| Следующая / предыдущая вкладка | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Отменить / Повторить | `Ctrl+Z` / `Ctrl+Y` (или `Ctrl+Shift+Z`) |
| Найти / Заменить / Перейти к строке | `Ctrl+F` / `Ctrl+H` / `Ctrl+G` |
| Найти далее / назад | `F3` / `Shift+F3` |
| Жирный / Курсив (только Markdown) | `Ctrl+B` / `Ctrl+I` |
| Сплит вкл./выкл. | `Ctrl+Shift+V` |
| Переключить разметка ↔ рендер | кнопка на панели |
| Масштаб: больше / меньше / сброс | `Ctrl` + колесо, `Ctrl+=` / `Ctrl+-`, `Ctrl+0` |
| Настройки | `Ctrl+,` |

Доступны и стандартные клавиши редактирования CodeMirror (`Tab` / `Shift+Tab` — отступ, `Alt+↑/↓` — переместить строки, `Ctrl+D` — выделить следующее вхождение и так далее).

## Установка

Каждая сборка создаёт два варианта:

- **Установщик** — `MDPad_<версия>_x64-setup.exe` (NSIS). Ставится для текущего пользователя, права администратора не нужны, регистрирует MDPad как редактор файлов `.md` / `.markdown`. Есть на английском и русском.
- **Портативная версия** — `MDPad_<версия>_x64-portable.exe` на странице релизов, а при локальной сборке — `mdpad.exe`.

Скачайте их на странице [Releases](https://github.com/lemitz/MDPad/releases) или [соберите из исходников](#сборка-установщика). Для работы нужен WebView2 Runtime: он уже есть в Windows 11 и в обновлённой Windows 10, а если его нет, установщик поставит его сам.

### Сделать MDPad редактором `.md` по умолчанию

Установщик регистрирует MDPad как редактор файлов `.md` и `.markdown`, но Windows 10/11 не позволяет программе назначить себя приложением по умолчанию без согласия пользователя. Щёлкните правой кнопкой по любому `.md`-файлу → **Открыть с помощью** → **Выбрать другое приложение** → **MDPad** → отметьте **Всегда использовать это приложение**.

## Разработка

Требования:

- [Node.js](https://nodejs.org) 20.19+ или 22.12+
- [Rust](https://rustup.rs) stable (1.77 или новее)
- Обычные [требования Tauri](https://v2.tauri.app/start/prerequisites/) для Windows (инструменты сборки MSVC, WebView2)

```bash
npm install
npx tauri dev        # запуск десктопного приложения с горячей перезагрузкой
npm run dev          # только фронтенд (Vite dev-сервер на :5173, без доступа к файлам)
npm test             # тесты фронтенда (vitest)
cd src-tauri && cargo test   # тесты Rust
```

Тесты покрывают определение кодировок и их круговое преобразование (включая Windows-1251 и UTF-16), логику переключения жирного и курсива, определение языка интерфейса и обработку путей на стороне Rust (аргументы командной строки, кириллические пути с процентным кодированием).

## Сборка установщика

```bash
npx tauri build
```

- Установщик: `src-tauri/target/release/bundle/nsis/MDPad_<версия>_x64-setup.exe`
- Портативный exe: `src-tauri/target/release/mdpad.exe`

Релизный профиль настроен на размер (`opt-level = "s"`, LTO, символы вырезаны).

[Windows workflow](.github/workflows/release.yml) запускается для pull request в `main`, версионных тегов и ручных запусков. Он проверяет, что версии npm, Rust и Tauri совпадают, запускает оба набора тестов, собирает установщик и портативный exe и загружает их вместе с `SHA256SUMS.txt` как артефакт `mdpad-windows`. **Релиз на GitHub публикуется только при пуше версионного тега**, с текстом из [`RELEASE_NOTES.md`](RELEASE_NOTES.md).

После слияния релизного pull request опубликуйте новую версию из обновлённой ветки `main` (замените `vX.Y.Z` на версию из `package.json`):

```bash
git switch main
git pull --ff-only
npm run check:release -- vX.Y.Z
git tag -a vX.Y.Z -m "MDPad vX.Y.Z"
git push origin vX.Y.Z
```

Не ставьте тег на feature-ветку: тег должен указывать на влитый коммит. Ручной запуск workflow собирает артефакты для скачивания, но релиз не публикует.

## Структура проекта

```
index.html                 оболочка приложения: заголовок, вкладки, панели, строка состояния
src/
  main.ts                  документы, вкладки, режимы, горячие клавиши, восстановление сессии
  editor.ts                настройка CodeMirror 6, тёмная подсветка, Ctrl+B / Ctrl+I
  preview.ts               markdown-it → DOMPurify → панель превью
  inline-edit.ts           правка блоков прямо в превью
  sync.ts                  синхронизация позиции редактора и превью по строкам
  encoding.ts              определение и кодирование кодировок и окончаний строк
  io.ts                    диалоги открытия и сохранения, IPC-вызовы в Rust
  i18n.ts                  строки интерфейса на английском и русском
  settings.ts              сохраняемые настройки
  ui.ts                    диалоги «Сохранить изменения?» и «Настройки»
  model.ts                 модель документа
  styles.css               тёмная тема
src-tauri/
  src/main.rs              запуск Tauri, один экземпляр, пути файлов из командной строки
  src/fsops.rs             команды read_file и атомарная write_file
  tauri.conf.json          окно, CSP, сборка и ассоциации файлов
  capabilities/            разрешения главного окна
scripts/check-release.mjs  проверка метаданных релиза: версии, тег, текст релиза
.github/workflows/         сборка релиза для Windows
```

Разделение ответственности намеренное: Rust-часть ничего не знает ни про Markdown, ни про редактирование — она читает и пишет байты, занимается окном и диалогами и передаёт пути файлов из командной строки. Всё, что касается документов, кодировок и интерфейса, живёт во фронтенде на TypeScript.
